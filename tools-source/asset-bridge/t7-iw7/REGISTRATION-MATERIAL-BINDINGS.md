## Closed report and refusal rules

The contract lists 41 outer keys, nine row keys, the existing ten snapshot keys
and the exact native pin. Rows are the ordered prefix index0..6 of the one
copied table. A complete global result requires seven rows, one matching MODEL
registration, successful zone load, no callback/search refusal or duplicate,
and a final recheck of the whole table/model/material chain. Hash and usage are
the actual copied uint32/uint16 values, not an allowlist or semantic mapping.

Each row independently attempts two protected 264-byte headers and twice-owned
names. The original MODEL/material0/table/selected row are rechecked within
that callback before its DTO is created. An unreadable header, invalid raw bool,
unstable name or copy fault refuses that row and still permits subsequent rows.
`binding_rechecked` equals the snapshot's successful observation flag.
`raw_name` and `leading_comma_reference` are null on refusal. Names preserve raw
UTF-8 bytes; one leading comma indicates a reference. An ordinary name alone
does not establish a full image definition.

Outer and row `registration_chain` fields close the numeric MODEL/material/table
association; the row additionally publishes the copied image-field value.
These are diagnostic hex integers, never an invitation to dereference them
later and never proof of engine object identity. No F2 binding4 success or
lookup-stage equality is required for the new seven-row capture.

`refused=false` describes a complete **enumeration window**, even when one or
all seven image snapshots independently refuse. A structural failure can retain
a diagnostic prefix of zero to seven rows with `refused=true`. A duplicate or
search/zone failure also refuses the global result. The entry logs this bounded
report before throwing on global refusal, giving a nonzero native exit. A
complete window can exit0 with refused image rows. A report from any other
failed process remains failed-process evidence.

`header_copies` sums complete copies in published snapshots, from zero to14.
`completed_header_bytes` is that sum times264, or null after any partial-copy
fault or structural catch; it does not estimate faulted writes. The header
attempt ceiling is3696 bytes, seven times two times264. Each name copy is bounded
to255 UTF-8 bytes plus NUL. C0 controls refuse per row before DTO publication:
seven maximally escaped control names duplicated in raw name and DTO would
already exceed32 KiB. Quotes, backslashes and non-ASCII UTF-8 are not normalized.
The shared metadata-read budget remains64 KiB and output remains32 KiB; the
renderer stays within the existing192-KiB CLI source ceiling.

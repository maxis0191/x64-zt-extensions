The existing T7 producer consumes four exact retained H text files through
`--image-provenance-fixture-proof-root`. Their fixed lengths/hashes and actual
source, synthetic scope, successful compile/test exits, original NoExit context,
input rechecks, guards, terminal exit and fresh empty closure are verified.
Their referenced EXE/OBJ paths are never opened by this proof reader. H qualifies
only the unchanged observer/entry/fixture source pins; a changed API cannot use
its proof. Without that proof, `SourceOnlyPending` and the hard Run refusal remain.

Proof-qualified DEFAULT keeps candidate pins null and all six execution/readiness
flags false. It returns before input/tool reads, provider imports or admission.
CPP enablement describes a reviewed recipe intent, not a compiled candidate or
permission to execute it. An exact coordinator GO and the existing original H1
host/job/resource lifecycle are still required. Memory admission remains the
shared TelemetryOnly policy; no numeric minima are introduced.

`--image-provenance-v1 --image-metadata-v1` adds a finite extension to the same
compiled CLI. Its separately invoked native option is:

    -t7-iw7-image-metadata-v1 mp_freerun_04 p7_fre_platform_cap_02 0

It selects the fresh nondefault MODEL lookup, LOD0/slot0/binding4/hash0xA0AB1041,
then reuses G3 `header_capture` and the G2 association/name/header rechecks.
Exactly two matching aligned owned 264-byte headers are required before the
reviewed scalar mapper publishes four physical descriptors. The original F2
entry and schema remain unchanged. F2, G2, G3 and their frozen source contracts
are not edited. No IMAGE lookup, new reader, pixel read, pointer repair, provider
query, extraction or engine write is added.

Review found that G2's original `image_metadata` calls a typed bool view before
the new mapper. The metadata renderer therefore derives one guarded G2 source
fragment from its exact immutable pin. A thread-local RAII scope enables raw
byte188 validation on the actual owned GfxImage in `reader.one` before its typed
return, and in `image_metadata` before `resident_image::view`. The guard restores
its prior state on nested scopes and exceptions. Other modes keep it inactive.
The CLI and fixture use the same generated fragment. This is not a check of a
different snapshot, nor a reference into live memory.

The closed outer schema is `iw7.t7-selected-image-metadata/1`; its nested mapper
schema is `iw7.t7-selected-image-header-metadata/1`. Success has null failure_stage
and reason, two copies and all header/name/association flags true. Any refusal

Output stays within 32 KiB, including a closed serialization refusal fallback.
Runtime ABI, atomicity, lifetime, retention, pixels and Ready remain false.

The extension has a dedicated 160 KiB CLI source cap and 320 KiB preparation
payload cap. Historical 128 KiB CLI and 256/288 KiB payload limits remain intact.
Its exact added source/generated bindings are finite; the four H proof bindings
and existing one TZRES proof are checked separately before the historical set.
No arbitrary input/header/tlog pin or native admission scope is broadened.

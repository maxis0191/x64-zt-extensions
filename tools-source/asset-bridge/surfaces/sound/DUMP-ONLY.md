# DumpOnly from the qualified FLAC Build C

This closed profile reuses `Prepare-SoundFF.ps1`, `Build-SoundFF.ps1`, the existing
sound transaction, original BuildJob ownership and unchanged shared providers.
It admits exactly `dump,read`; it cannot build or verify a new FF. The preserved
F FF/SABL/SABS are guarded hardlink inputs and retain their original artifact
paths. The existing 72 stock entries and 8 GiB physical / 11 GiB commit budget,
64 MiB output bound, phase deadlines and restoration logic are unchanged.

Preparation requires the actual successful C receipt and supervisor state before
creating a Plan. It binds all 17 native phases, the 103-case C++ header probe,
qualified original-job closure, six final artifact identities, before/after input
proof, 1418 disposed guards and released lease. Its exact metadata pins are
`dfe3d7d1ed0d9b3c4ad334fc64d1f3f277508c468df034f05cffd2505f3944f4`
and `99c5c35fe43ad90bb192db8902dc718402fb901dd2cc6f6689d790e82a5ba149`.
The observed candidate is 21705728 bytes, SHA-256
`cef411cf9b4de69be02cb4017aabd964e9143e340e211188daa6b6bab366493a`.
Builds A and B remain failed attempts; this does not requalify either.

Default Plan validation opens only source and small text evidence. Python and
original WAV/FLAC pins are copied from F metadata into deferred `PayloadInputs`.
Their guards/hashes, the candidate binary and preserved FF/SAB reads occur only
after the existing atomic admission. Cleanup also avoids payload reads if admission
fails. The preserved F Plan/state and every original reader source remain bound;
no original audio or bank is regenerated to prepare this profile.

The reader explicitly selects `DumpOnlyC`: STREAMINFO min/max block size must be
4096/4096; both frame-size fields and MD5 remain zero. Every other original FLAC
byte, including seek points, frames and final length, must compare exactly.
The default `NativeDumpF` expectation remains 1024/1024. Inventory is explicitly
labelled `PreservedBuildF`, since native dump stdout has no inventory callbacks.
It proves the historical inventory of the identical F bytes, not a new verify run.

Successful DumpOnly would retain its actual dump size/hash under admission in
`DumpFlac`, after the reader and again during final restoration proof. It would
report `SoundDumpOnlyBytesVerified`, never codec, standalone FLAC conformance,
playback or Ready. A later codec profile requires that new observed dump receipt;
`OriginalSource` and `NativeDumpF` are unchanged.

Validation before any native dump: 34 Python cases (including synthetic 4096
headers, historical 1024 rejection and seek/frame/MD5/trailing mutations); 24 C
evidence cases, 13 Plan mutations, default Plan and pre-admission refusal; 12
DumpOnly and 14 historical transaction cases using mock ownership/admission with
real tiny-file restoration; 9 final accounting and 11 deadline cases. No stock,
candidate binary or retained audio payload was opened by those source tests.

Native dump and codec execution still require separate coordinator approval.

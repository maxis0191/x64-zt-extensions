# Authored ModelFF admission and original-owner route - Source checkpoint

This connects the original authored project to the existing ModelFF entry,
transaction and H1 original-job caller. No authored FF has been built or read
back by this change. The separate B2 standalone writer result remains its frozen
producer/geometry evidence. Material, FF, recipient/normal/shader ABI, pixels,
physics/contact and owner acceptance remain unqualified.

## One admission, including input staging

`Build-ModelFF.ps1` accepts the existing prepared `SourceRoot`. Its optional
`AuthorProjectSource`, `AuthoringPlan` and `AuthoringPlanSHA256` instead identify
an original Source project and a fresh future stage. Before admission this mode
reads only the bounded author-input metadata and original text descriptor. It
does not fabricate a ModelFF plan/3. DryRun remains Source-only and creates no
native type, process, stage, reservation or tool/stock/asset observation.

The actual context, original PSVariables, state, guards and publication records
are rooted before the entry's single admission. All opaque input reads, NativeJob
and file-identity imports, candidate qualification, stock observations and native
operations follow that admission. The Source project is copied into a fresh
owned temporary directory; originals and copied inputs remain guarded.

The fixed Python argument code calls SDK29's existing `stage_ff_inputs` API through
the same `Invoke-ModelFFTool` dispatcher and H1 owner. It uses `-B -S -c`, four
separate path arguments and a cleared child environment. SDK29 and its fourteen
transitive Source files are bound to its immutable Source workspace. The SDK
package is not edited and its old Build-ModelFF entry is not invoked. The caller
measures the actual plan file inside that original Python job, then compares the
returned path/length/hash and holds the real plan/evidence after job closure.

Only the SDK creates the actual plan/3, DDS/material payloads and writer evidence.
Its typed closure validator remains the authority for the B2 writer snapshots;
no duplicate serializer or receipt parser is introduced. The Source recipe,
two artifacts and all three writer publications are enrolled before that call.
A partial/failed stage is retained for diagnosis and cannot advance to FF work.

The entry then uses its existing strict community candidate gate, FF build,
offline inventory and dump, followed by the measured B2 native geometry reader
and existing authored image/material reader. These operations use original H1
jobs in the same context and admission. Exit zero alone never qualifies an FF:
the actual file, unique inventory, both independent readbacks and restoration
must pass. Group and phase deadlines include setup and checks immediately before
factory creation and Start; the actual returned owner is retained before a
post-construction deadline can throw.

## Restoration, unknown state and publication

Source, payload and code guards stay held through the operation. Stock guards
are rechecked after original job closure, then closed immediately before the
existing transaction unlinks borrowed aliases, respecting Windows share-delete
rules. The same context/admission and original byte/identity records remain.
Restoration checks original source identities and metadata. A final check reopens
against those same pins and verifies current content before release.

The optional existing restore callback runs after restoration/source proof and
before reservation release. It publishes a bounded native snapshot through the
existing H1 receipt writer, flushes/readbacks/hashes it, then closes input guards.
A final closure publication binds that original snapshot and its confirmed input
closure, following the existing two-phase writer protocol. Deadline checks follow
publication/guard enrollment and the final readbacks; expiry keeps CanExit false
with the original root and publication guards retained.
Stock uses a local 16 GiB streaming file bound for both initial and final guards,
hashing the same retained handle. H1's generic 64 MiB bound is unchanged.
Publication guards and the actual AppDomain root remain until final verification. Unknown jobs, failed
restoration, changed inputs or failed publication preserve the exact references
and prevent CanExit. Authored recovery must use that retained original host;
a new process cannot reconstruct ownership from `state.local.json`.

Source validation uses synthetic metadata, fake clocks/owners and injected
restoration/publication failures. It does not constitute an admitted stage,
candidate observation, FF, stock mutation, renderer or gameplay result. A fresh
reviewed capsule and distinct exact-tuple GO are still required for those steps.
